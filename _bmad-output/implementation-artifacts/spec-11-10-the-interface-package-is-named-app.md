## Intent

**Problem:** The interface lives in `packages/web` as `@archant/web`, reached through `pnpm web`. The name `web` is wanted later for a public or documentation site, and renaming then would collide with the interface.

**Approach:** Move `packages/web` to `packages/app` with `git mv`, rename the package `@archant/app` and the root alias `app`, regenerate the lockfile, and update every live reference outside `_bmad-output/` history. Behaviour does not change.

## Boundaries & Constraints

**Always:**
- `git mv packages/web packages/app`, so file history follows the rename.
- Outside `_bmad-output/`, `git grep -E "packages/web|@archant/web|pnpm web"` returns nothing once the story ships. That covers code comments and test data too, not only the files the epic names.
- `pnpm-lock.yaml` is regenerated by `pnpm install`, never edited by hand, and `pnpm install --frozen-lockfile` passes on the result.
- The container still serves the interface: the image builds `packages/app/dist` and sets `WEB_DIST=/app/packages/app/dist`.
- `ARCHITECTURE-SPINE.md` describes the current architecture, so its three references move to `packages/app` and `@archant/app`. Every other file under `_bmad-output/` (epics, story specs, deferred work) keeps its text as written.

**Never:**
- No rename of the `WEB_DIST` variable. A plain Node host sets it by hand, and a renamed variable would silently stop serving the interface after an upgrade.
- No rename of symbols that mean "the browser's side" rather than the package, such as `WEB_URL` in `e2e/settings.ts`.
- No change to source code behaviour, routes, dependencies or scripts other than the alias.
- No new check or script guarding against the old name.
