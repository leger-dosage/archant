## Intent

**Problem:** A bank account's first sync always reads 90 days back (`FIRST_WINDOW_DAYS` in `services/sync.ts`), so the owner's BoursoBank history stopped three months back, where Sure lets the user choose the start date on its setup screen.

**Approach:** Store Sure's `sync_start_date` on `bank_connections`, offer it on the connection's accounts page while a bank account is left to link, save it with the links, and let `windowStart` read it for an account that never synced. Story 25.1 of `epics.md` is the acceptance contract; this spec adds what reading the code and Sure settled.

## Boundaries & Constraints

**Always:**
- Column `sync_start_date` (text, nullable) on `bank_connections`, migration `0059` generated by `pnpm data generate`. `BankConnectionRecord` returns it as `syncStartDate`.
- `POST /api/bank-connections/:id/accounts` takes an optional `syncStartDate` (`z.iso.date()`) beside `links`. The service checks it in `APP_TIMEZONE`: after today is `date_in_future`, before `addMonths(today, -24)` is the new `sync_start_too_early`, both under path `syncStartDate`, checked with the links so one refusal writes nothing. When present it is saved in the links' transaction; absent leaves the stored date, as Sure's `update!` only `if params[:sync_start_date].present?`.
- `windowStart(lastSyncedAt, day, timeZone, oldestPending, syncStartDate)`: never synced → `syncStartDate ?? addMonths(day, −3)`, Sure's `3.months.ago`; synced → its last sync minus seven days, whatever the date; then never after the oldest pending entry, as today.
- An account the link creates opens on the earlier of two years back and the day before the connection's start date, so the start day's lines are not refused as on or before the opening date.
- The page shows the field on every visit while a bank account is left to link, as Sure's `setup_accounts`: label « Commencez à synchroniser les transactions à partir de », value the stored date else three months before today in the browser (`monthsAgo(3)` in `lib/dates.ts`, Rails' `3.months.ago` clamping), hint Sure's « Sélectionnez jusqu'où vous souhaitez synchroniser l'historique des transactions. Maximum 2 ans d'historique disponible. ». The stored date unchanged is not sent again, so a date chosen two years ago never refuses a later link. `DateField` gains optional `min`/`max`, disabling the calendar's days outside them, Sure's `min`/`max`. « Valider » sends the date with the links; a refused date shows its message under the field.
- A bank that returns less than asked is a normal sync: no error, no warning, whatever it returned is kept.

**Never:** no re-read of older history for a synced account; no date on renewal or anywhere else than the accounts page; no change to the 89/60/30 fallbacks; no MCP tool or export change (Sure's export and assistant leave `sync_start_date` out); no client-side range check the server does not make.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected |
|---|---|---|
| Default | today 2026-09-24, no date stored | field shows 24/06/2026; first sync without a stored date reads from 2026-06-24 |
| Chosen | `syncStartDate: "2025-01-15"` with links | stored; first sync `date_from=2025-01-15` |
| Oldest | `2024-09-24` | accepted; new account opens 2024-09-23 |
| Too early | `2024-09-23` | 400 `sync_start_too_early` on `syncStartDate`, nothing linked or stored |
| Future | `2026-09-25` | 400 `date_in_future` |
| Not a date | `"2025-02-30"` | 400 `invalid_format` |
| Already synced | stored date moved, account synced yesterday | window = last sync − 7 days |
| Later link | second bank account linked a week later | its first sync reads from the stored date |
| Short bank | asked two years, bank returns 90 days | `synced`, `lastError` null |
| Viewer | POST with a date | 403, nothing stored |

## Implementation Notes

- The viewer case is the generic walk of `routes/middleware/roles.spec.ts`, which refuses every writing route to a viewer; no bank-specific test was added.
- The stored date is read through `activeConnection`, which `linkBankAccounts` already calls; the sync reads it once per run.
- The e2e fake's `Banque Historique` keeps one line 400 days back, listed only when `date_from` reaches it: the line on the account page proves which date the first sync asked for, and that a bank holding less than two years ends without an error.
- The field's text is the browser's, as every `DateField`; the server checks the range in `APP_TIMEZONE`, which the suite pins to the browser's zone.

## Design Notes

Assumptions taken without the owner, each from Sure or the epic:
- Field shown on every visit while a bank account is left to link, as Sure's setup (see the change log).
- Server-side range check: Sure has only the input's `min`/`max`; the story asks for `VALIDATION_ERROR`. The bounds are Sure's (`2.years.ago`, `Date.current`), in `APP_TIMEZONE`.
- The page's default and the sync's fallback are both three calendar months, Sure's view and importer (see the change log).
- Opening date before the start day: Sure's `OpeningBalanceManager#default_date`, the earlier of two years back and the day before the oldest entry, and its `date_error` refusing an opening on or after it.
